# Guarded VMInterface importer (not yet authorized for production apply)

The original Proxmox guest template/base image VMID 362 stays unchanged. The import plan creates its NetBox VMInterface but deliberately holds its duplicated MAC assignment; VMID 366 keeps the matching live MAC. Neither Proxmox guest nor bridge configuration is modified.

The script `netbox/import_guest_nics.py` is intended to run inside a NetBox 4.7 Django `manage.py shell` process. It reads a private JSON preview generated by `netbox/preview_guest_nics.py` and validates exact 31 VMIDs / 31 interfaces / 30 MACs / held VMID 362, preview age, current cluster membership and any pre-existing VM interfaces or MAC conflicts.

Dry-run is the default. Do not run apply until an independently verified recent PostgreSQL backup exists, an operator checks the preview, and the template use is understood. Apply is all-or-nothing in `transaction.atomic()`, uses `VMInterface.full_clean()`, `VMInterface.save()` and `set_primary_mac_address_from_value()` for MAC objects. The importer never creates VM objects, VLANs, IP addresses, or network bridges.

The original preview file includes private MACs and VM IDs; it must be copied to the NetBox host using an approved, protected transfer method with mode 0600, not committed to Git or posted in public output. Bridge names are retained as text descriptions only, not assigned to NetBox VMInterface.bridge.

Current branch is for review and offline tests. Do not run against production until live NetBox Django shell dry-run and a fresh snapshot are successfully verified.
